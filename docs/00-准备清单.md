## 结论

- 可行，本机条件基本齐备：游戏已装、.NET SDK 已装、反编译工具已有、示例模组已实测编译通过。
- 只差 2 件：游戏目录里的 `dev.txt`（调试工具开关）、发布用的 `steamcmd`（不发布则不需要）。
- 工程源码不放游戏目录，改放工作区 `src\`（见 2.2）；加载器只认 `<游戏>\Mods\`，源码位置不影响加载。
- 最小可跑模组 = `manifest.xml` + 一个实现 `IMod` 的 DLL。资源（贴图/音效/本地化/手册）可选，目录与命名固定。
- 清单里 `<GameVersions>` 写 `1.0.0` 即可覆盖当前 1.0.0.x 全部修订（L1407-1418）。

## 2. 准备清单（逐项可执行）

### 2.1 开调试工具：`dev.txt`
- 在游戏根目录建**空文件** `dev.txt`，确认不是 `dev.txt.txt`（L136-137）。
- 只在启动时检查一次，增删后必须重启游戏（L138）。
- 启动日志会出现 `[DevTools] Developer tools enabled`；若按 F8 无反应，查 `Player.log` 里该行给出的路径（L142）。
- F8 = 调试控制台（日志/命令），F9 = 开发菜单（刷物品、改状态）；`dev.txt` 不要随模组发布（L140）。

### 2.2 建工程：源码放工作区（已定）

游戏加载器只认 `<游戏目录>\Mods\<模组>\`，**源码放哪里都行**。本项目把源码根目录定在当前工作区：

```
D:\DSH_WORKZONES\Probably-Stolen-DEVELOPMENT\
├── src\
│   ├── Directory.Build.props      ← GameDir / ManagedDir / 构建后自动安装，所有模组共用
│   └── <Project>\
│       ├── <Project>.csproj       ← 只写 4 个引用
│       ├── ModEntry.cs
│       ├── manifest.xml
│       ├── Textures\Items\…       ← 资源按约定目录放，构建时整目录拷进 Mods
│       └── Sounds\ Localization\ LootTables\ Books\
├── docs\                          ← 本目录
├── ref\api\                       ← 反编译参考
├── build\Mods\                    ← 临时/预演安装目录（不装进游戏时用）
└── ds-modding-docs\               ← 官方文档仓库（只读参考）
```

- `src\Directory.Build.props` 解决两件事：把文档里的相对路径 `..\..\Probably Stolen_Data\Managed` 换成 `$(ManagedDir)`；构建后把 DLL + `manifest.xml` + 资源目录拷到 `$(ModInstallDir)`（默认 `<游戏>\Mods\<工程名>`）。
- 游戏路径可覆盖：`-p:GameDir="D:\...\Probably Stolen"` 或环境变量 `PROBABLY_STOLEN_DIR`，不必改文件。
- 只做编译验证、不装进游戏：`-p:ModInstallDir=<工作区>\build\Mods\<工程>`；完全跳过安装：`-p:DisableModInstall=true`。
- 已用示例 `src\LearnerMod` 实测：0 错误 0 警告，`manifest.xml`、`LearnerMod.dll`、`Textures\Items\health_pack.png` 均按原相对路径落到安装目录。
- `.csproj` 仍必须引用 4 个 DLL 且 `<Private>false</Private>`：`Assembly-CSharp`、`UnityEngine`、`UnityEngine.CoreModule`、`0Harmony`（README L78-106）。
- 官方 `create-mod.bat` 的流程仍可用，但它假定工程在游戏目录的 `Modding\` 下；走本布局时不用它。

### 2.3 写 `manifest.xml`（必需，缺了整个文件夹被跳过）
| 字段 | 要求 |
|---|---|
| `ID` | 必填、唯一；仅 ASCII 字母/数字/`_`/`-`/`.`，不以 `.` 开头，≤64 字符；会成为玩家磁盘上的文件名（README L144） |
| `Name` | 模组菜单显示名；F8 日志前缀 `[Name]:`（L121） |
| `Author` / `ModVersion` / `Description` | 常规元数据 |
| `GameVersions` | 四段版本；`1.0.0` 覆盖 1.0.0 全修订；**不能写商店标签 `100-Rev14`**，要写 `1.0.0.14`；可写闭区间 `1.0.0.5 - 1.0.1`（L1407-1426） |
| `Prerequisites` | 依赖模组 ID，无则 `<Prerequisites />`，每依赖一条 `<Mod>` |
| `Assemblies` | **必填**，每个要加载的 DLL 一条，相对路径、按加载顺序；文件夹里多余 DLL 会拒绝启用 |
| `Capabilities` | **必填**，通常 `<Capabilities />` 空标签 |

### 2.4 写入口类（实现 `IMod`）
```csharp
public class ModEntry : IMod {
    public void Init(ModManifest manifest) { /* 一次性初始化；ModLog 在此构造 */ }
    public void OnEnable()  { /* 钩子订阅放这里 */ }
    public void OnDisable() { /* 撤销订阅、debug 按钮 */ }
}
```
- 三个方法都在**主菜单**阶段运行：此时没有存档、没有游戏内管理器，不要生成物品/读存档（README L203）。
- 运行时用 `ModLog`（自动加模组名前缀），不要用 `Debug.Log`（L91-121）。

### 2.5 构建与部署
```powershell
dotnet build -c Release      # 产物 bin/Release/netstandard2.1/<Project>.dll
```
- 手工部署：DLL + `manifest.xml` 一起放进 `Mods/<Project>/`（README L219-229）。
- 自动部署：用 `create-mod.bat` 生成的工程（构建后直接拷进 `Mods/`）。
- 反复改代码时会因哈希变化要求"审核并启用"；在模组详情面板开一次**开发者模式**即免（L1508-1510）。

### 2.6 激活与验证
1. 启动游戏 → 模组菜单"未启用"列出现你的模组 → **启用** → 重启游戏（停用/排序都在下次启动生效，L1815）。
2. F8 控制台看到 `[Name]: ...` 输出即成功。
3. 启用时游戏会扫描 DLL：`mod-scan <你的ID>` 看 `declared` 是否覆盖 `detected`，有 `DEPRECATED`/拒绝标记必须处理（L1489-1497）。

### 2.7 查游戏 API（可选但强烈建议）
- 已有 `ilspycmd`：
  ```powershell
  ilspycmd -l c "<游戏>\Probably Stolen_Data\Managed\Assembly-CSharp.dll"
  ilspycmd -t ModHook "<游戏>\...\Assembly-CSharp.dll"
  ```
- 已导出参考：`ref/api/`（IMod、ModManifest、ModLog、ModHook、ModHelper、ModCapability、ModItemDirectory）。
- 文档未覆盖的玩法系统，直接查 `Assembly-CSharp.dll`；`ModHelper` 的 `Add*` 系列是内容扩展主入口。

## 5. 能力声明与红线（发布前必读）

- 能力取值：`files`、`network`、`process`、`steam`、`steam-auth`、`window`（L1451-1460）。
- 2026-12-10 起拒绝：`dynamic-code`、`native`、`reflection-external`、`threads`（今天带警告接受）。
- 免声明：物品/机器/钩子/Harmony 补丁/配置/模组数据/精灵/音效/本地化/手册/自定义 UI（L1447）。
- 用到未声明 → 启用被拒；多声明允许（L1464）。
- 一律拒绝（节选，L1466-1485）：启动外部程序、可执行/加密嵌入资源、≥1024 字符 base64 常量、`UnpatchAll(null)`、补丁加载器/信任层、未列出的 DLL、自带 `0Harmony`/MonoMod/Cecil、`[ModRestricted]` 方法（`SaveFiles` 全部、`PaperEditorFiles.OpenFolder/OpenFile`、`ModUIManager.OpenModFolder`）。
- 文件读写走 `ModData` 辅助（`WriteModDataFileText` 等，限 `persistentDataPath/ModData/<modId>/`），不需要 `files` 能力；绝对路径、`..` 会被拒（L1512-1535）。
- 行为准则硬性规则（`CodeOfConduct.zh-CN.md` L10-30）：无恶意代码；不收集玩家数据（功能必需且仅使用时除外）；如实声明能力、不藏行为；不误导、不冒充本体；不故意崩溃/卡顿；不未授权再分发他人作品或游戏素材；不破坏他人模组；不发布未发布内容；Discord 上不得发 NSFW。

## 6. 资源与目录约定（不递归！）

| 目录 | 内容 | 规则 |
|---|---|---|
| `Textures/Items/` | 物品图标 | `.png`/`.jpg`；点采样、无 mipmap；尺寸为网格 `gridSize` 整数倍；键 = 文件名去扩展名（L314-327） |
| `Sounds/` | 音效 | `.wav`/`.ogg`/`.mp3`；键 = `<modId>:<文件名>`；不要自建 `AudioSource`（L329-358） |
| `Textures/`（`Items/` 外） | 其他贴图 | 只进内存，需自绘（L369-375） |
| `Textures/Paper/` | 手册贴图 | 平滑 UI 精灵，双线性、无 mipmap（L383-385） |
| `Localization/` | `en.csv`、`zh.csv`… | UTF-8、无表头、`键,文本`，首个逗号后全是文本；`ModHelper.GetLocalized` 读（L387-443） |
| `LootTables/*.json` | 掉落表 | `tables`/`groups`/`patches`，多文件按字母序（L647-675） |
| `Books/<id>.json` | 纸质手册 | 可用 F9 Paper Editor 生成（L819-857） |
| `preview.png` | 模组预览图 | 放模组根目录（L283） |

坑：子目录里的 PNG 会被**静默忽略**，必须直接放在上述目录（L303）；`spriteKey` 是文件名而不是路径。

## 7. 钩子（44 个，`ModHook` 静态事件）

- 层级：顾客生成 `VeryEarly→Early→Normal→Late→VeryLate`；存档载入 `Init→Early→Normal→Late`；其余多为 `Early→Late`；顺序无关时用 `Normal`（L504-508）。
- 订阅写在 `OnEnable`、取消写在 `OnDisable`；每个订阅者独立 try/catch（L468-500）。
- **物品目录**：`OnModItemDirectoryInit(ModItemDirectory)` → `dir.Add(id, factory)`，工厂内 `ItemDirectory.CreateEmptyItem` + `SetSpriteAndShapeFromMod(modId, spriteKey)`（L510-547）。
- 生成物品：`ModHelper.SpawnItem(id)` + `MoveItemToInventory/FrontCounter/BackCounter/DisplayCase/Trash/Afterhours`；**必须在局内钩子**（如 `OnGameLoadedInit`）调用，主菜单调用会 NRE（L530-542）。
- 分类清单：
  - 顾客/店铺：`OnGenerateCustomer*`、`OnShutterOpened*`、`OnShutterClosed*`、`OnGoingSleep*`、`OnWakingUp*`、`OnLeavingStore*`、`OnReturningStore*`、`OnHandlingNightlyServices*`
  - 库存/提示：`OnPlaceInventorInventoryItem*`、`OnCreateTooltip*`、`OnCreateDevTooltip*`
  - 存档/开局：`OnGameLoaded*`、`OnNewGameStarted`、`OnDifficultyApplied`、`OnGameOver`
  - 资源/掉落：`OnModAssetsLoaded`、`OnLootTablesLoaded`、`OnLootRolled`
  - 系统/UI：`OnPaperOpened`、`OnModConfigApplied`、`OnNetworkUpgradeUnlocked`
  - 夜间：`OnAfterhourArrive*`、`OnAfterhourLeave*`、`OnAfterhourEventStarted/Ended`
- 优先用钩子而不是 Harmony：更快、更新后不易失效（L466、L1618）。

## 9. 发布：Steam 创意工坊

- 游戏内没有上传按钮；用 Valve `steamcmd`，需拥有本游戏的 Steam 账号（L1583）。**本机尚未安装 steamcmd**。
- 一个工坊物品 = 一个模组文件夹（根目录 `manifest.xml`），加载器与本地 `Mods/` 同一套，代码无需改动（L1568）。
- 复制模组文件夹 → 根目录放 `<1MB` 的 `preview.png` → 写 `my_mod.vdf`：
  ```vdf
  "workshopitem" {
    "appid" "4348910"
    "publishedfileid" "0"        // 0 = 新建；更新时填已有 ID
    "contentfolder" "D:\\...\\my_mod"
    "previewfile" "D:\\...\\preview.png"
    "visibility" "2"             // 0 公开 / 1 仅好友 / 2 隐藏（首测用）
    "title" "..." "description" "..." "changenote" "..."
  }
  ```
- 发布/更新：`steamcmd +login <账号> +workshop_build_item "<vdf 路径>" +quit`；首次需在 Steam 网页接受一次工坊协议；steamcmd 会回写 `publishedfileid`，保留该 vdf，以后同一命令即更新，订阅者自动收到（L1586-1612）。
- 本地 `Mods/` 与工坊同 `<ID>` 时优先用本地副本（L1576）。创意工坊仅正式版可用（L1579）。
